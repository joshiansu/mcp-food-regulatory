The problem

Regulatory research is slow and painful

If you make food or supplements, you know this struggle.

😩

Hours lost on government websites

Digging through PDFs and regulations to check if a single claim is allowed can take an entire afternoon.

🌍

Every market has different rules

What's permitted in the EU may be banned in the US. Staying on top of 7 rule sets simultaneously is nearly impossible.

📋

Rules change without warning

Regulations update constantly. Keeping track requires continuous monitoring you simply don't have time for.

💸

Hiring regulatory experts for basic claim checks is expensive — and often overkill for a quick yes/no answer.

The solution

Connect once, ask anything

Works with Claude, Cursor, Windsurf, Cline, and any MCP-compatible AI app. Add it in 2 minutes — no coding required.

1

Open Claude Desktop settings

Go to Settings → Developer → Edit Config. This opens a JSON file in your editor.

2

Paste the server config

Add this block and save the file:

{ "mcpServers": { "food-regulatory": { "url": "https://mcp-food-regulatory.vercel.app/mcp" } } }
3

Restart Claude and start asking

Ask Claude about any ingredient, market, or health claim in plain English — no special commands needed.

ℹ️ ChatGPT, Perplexity, and Grok do not yet support MCP natively — here are your options
A

ChatGPT — Create a Custom GPT with Actions

In ChatGPT, go to Explore GPTs → Create → Configure → Add Actions. Paste the MCP endpoint URL and describe the tools. This lets your Custom GPT call the regulatory API directly. Requires a ChatGPT Plus or Team plan.

B

Perplexity & Grok — Use an MCP bridge

Neither Perplexity nor Grok currently supports MCP connections. You can use a community bridge like mcp-proxy to expose the tools via a local REST API, then integrate that API via any supported plugin/function mechanism those platforms offer.

C

OpenAI API — Function calling

If you're building with the OpenAI API, use function calling. Define the regulatory tools as functions in your API request and call https://mcp-food-regulatory.vercel.app/mcp when the model requests them. See the GitHub README for the full tool schema.

🔌 For developers and custom integrations
1

Use the MCP endpoint directly

The server follows the MCP streamable-http transport spec. Any compliant client can connect using this URL:

https://mcp-food-regulatory.vercel.app/mcp
2

Standard JSON config

Most MCP clients (including Zed, Continue, custom agents) use the same config format:

{ "mcpServers": { "food-regulatory": { "url": "https://mcp-food-regulatory.vercel.app/mcp" } } }
3

Available tools

The server exposes 6 tools: search_health_claims, get_standard, search_standards, compare_markets, get_market_overview, and list_markets. See the GitHub README for full schema docs.

Examples

What can you ask?

Just talk to Claude naturally. Here are a few examples of what you can ask right now.

👤

Can I claim vitamin D supports bone health in the EU and Canada?

✓ PERMITTED — EU ✓ PERMITTED — Canada

EU: Authorized under EC 432/2012, Article 13.1 — "Vitamin D contributes to the maintenance of normal bones." Canada: Pre-approved Nutrient Function Claim under FDR B.01.500. Standard prescribed wording is required in Canada.

👤

Is a "prebiotic" claim allowed for inulin in the US?

— NOT DEFINED — US FDA

The US FDA has no pre-approved "prebiotic" health claim. Inulin qualifies as dietary fibre under 21 CFR 101. A Structure/Function Claim may be self-notified to the FDA, but requires a qualifying disclaimer on the label and an FDA notification within 30 days of first marketing.

👤

Compare calcium and osteoporosis claims across all markets

✓ EU ✓ US ✓ Canada ✓ Australia ✓ Japan ~ Philippines — Codex

Permitted in 5 of 7 markets with different required wording in each. Conditional in the Philippines (requires BFAD product approval). No specific standard under Codex. Each market also sets different minimum calcium content thresholds.
